# REQUIREMENTS.md

## Требования к проекту FluxBar (PRD)

### 1. Функциональные требования (Functional Requirements)

#### 1.1. Ядро и управление состоянием
- [ ] **FR-1.1**: Система должна позволять добавлять, удалять и модифицировать элементы бара (items) на лету через CLI или IPC без перезапуска основного процесса.
- [ ] **FR-1.2**: Поддержка гибкого позиционирования элементов: `left`, `center`, `right`, а также абсолютное позиционирование и группировка в стеки.
- [ ] **FR-1.3**: Встроенная поддержка "алиасов" (перехват и отображение нативных иконок из строки меню macOS, например, Wi-Fi, Bluetooth, MeetingBar).

#### 1.2. Система событий (Event System)
- [ ] **FR-2.1**: Генерация и обработка встроенных событий: изменение рабочего стола, фокуса приложения, громкости, яркости, состояния питания, медиаплеера.
- [ ] **FR-2.2**: Возможность регистрации и триггера кастомных событий: `fluxbar --trigger my_event --payload '{"status": "ok"}'`.
- [ ] **FR-2.3**: Поддержка триггеров по таймеру (polling) с настраиваемым интервалом (например, обновление данных каждые 2 секунды).

#### 1.3. Система плагинов (Plugin System)
- [ ] **FR-3.1**: Поддержка **Persistent Plugins**: плагин запускается один раз и общается с ядром через JSON-RPC (stdin/stdout или UDS), что исключает накладные расходы на создание процесса.
- [ ] **FR-3.2**: Поддержка **Wasm Plugins** (цель v2): выполнение community-плагинов в безопасной песочнице (Wasmer/Wasmtime) с ограниченным доступом к ФС.
- [ ] **FR-3.3**: Официальный `fluxbar-sdk` (Rust crate), упрощающий создание плагина до реализации 1–2 трейтов (например, `on_event` и `on_tick`).
- [ ] **FR-3.4**: Встроенный CLI-менеджер плагинов: `fluxbar plugin install github:user/repo`, который автоматически клонирует, собирает (если требуется) и регистрирует плагин в конфиге.
- [ ] **FR-3.5**: Изоляция сбоев (Fault Tolerance): падение плагина не должно приводить к панике основного бара. Хост должен автоматически перезапускать упавший плагин с экспоненциальной задержкой (exponential backoff).

#### 1.4. Кастомизация и рендеринг
- [ ] **FR-4.1**: Поддержка сложных макетов внутри одного элемента: иконка + текст + график + индикатор прогресса.
- [ ] **FR-4.2**: Плавные анимации (interpolation) для изменения ширины, цвета, позиции и прозрачности. Длительность и easing-функция (например, `ease_out_expo`) настраиваются.
- [ ] **FR-4.3**: Отрисовка векторных графиков (line graphs, bar charts) на основе переданных массивов числовых данных.
- [ ] **FR-4.4**: Обработка событий мыши: `mouse.clicked`, `mouse.scrolled`, `mouse.entered` с возможностью привязки к shell-командам или IPC-сообщениям.

#### 1.5. Конфигурация
- [ ] **FR-5.1**: Основной конфиг в формате `TOML` (человекочитаемый, с поддержкой комментариев и строгой типизацией).
- [ ] **FR-5.2**: Возможность модульной конфигурации: импорт файлов из директории `~/.config/fluxbar/plugins.d/`.

### 2. Нефункциональные требования (Non-Functional Requirements)

- [ ] **NFR-1 (Производительность)**: Потребление CPU в состоянии покоя < 0.5%. Время отклика на событие < 16 мс (для поддержки 60 FPS анимаций).
- [ ] **NFR-2 (Надежность)**: Ядро должно обрабатывать паники плагинов, разрывы соединений и некорректные JSON-сообщения без собственных сбоев (graceful degradation).
- [ ] **NFR-3 (Безопасность)**: Плагины не должны иметь прямого доступа к памяти ядра. Wasm-плагины должны быть ограничены в доступе к файловой системе и сети по принципу наименьших привилегий.
- [ ] **NFR-4 (Кроссплатформенность)**: Архитектура должна абстрагировать рендеринг и системные события (через trait-объекты), чтобы обеспечить возможность портирования на Linux (Wayland) в будущем, даже если первая версия таргетирует только macOS.

### 3. Технический стек

| Компонент | Технология | Обоснование |
| :--- | :--- | :--- |
| **Язык** | Rust | Безопасность памяти, производительность, отличная экосистема для CLI и системного ПО. |
| **Асинхронность** | `tokio` | Зрелая, высокопроизводительная асинхронная среда для IPC, таймеров и работы с сетью. |
| **Сериализация** | `serde`, `serde_json` | Стандарт де-факто для типизированного JSON-RPC, минимизирует ошибки парсинга. |
| **IPC** | `tokio::net::UnixStream` / `jsonrpsee` | Быстрая межпроцессная коммуникация без накладных расходов TCP-сети. |
| **CLI** | `clap` (с derive) | Мощный, эргономичный и типизированный парсер аргументов командной строки. |
| **Рендеринг (macOS)** | `objc2` + Core Animation | Нативный подход для идеальной интеграции с macOS, прозрачности и работы с NSStatusItem. |
| **Текст и шрифты** | `cosmic-text` | Современная, быстрая отрисовка текста с поддержкой лигатур, эмодзи и сложных скриптов. |
| **Wasm Host** | `wasmtime` (опционально, v2) | Безопасное и изолированное выполнение кода сообщества. |

### 4. Этапы разработки (Milestones)

#### 🚩 Milestone 1: MVP (Ядро и базовый рендеринг)
- Инициализация окна/статус-бара на macOS.
- Базовый парсинг TOML-конфига.
- Отрисовка статического текста и иконок (SF Symbols / Nerd Fonts).
- Простой CLI для команд `--add`, `--set`, `--remove`.

#### 🚩 Milestone 2: События и IPC
- Реализация шины событий (подписка на системные события macOS через `notify` или нативные API).
- Реализация JSON-RPC сервера на Unix Domain Socket.
- Поддержка базовых анимаций изменений (интерполяция ширины и цвета).

#### 🚩 Milestone 3: Система плагинов v1
- Создание и публикация `fluxbar-sdk` (Rust crate).
- Реализация хоста для persistent-плагинов (автоперезапуск, логирование, обработка разрывов связи).
- Референсные реализации плагинов: CPU/RAM monitor, Media player (на Rust и Python).

#### 🚩 Milestone 4: Полировка и Экосистема
- Поддержка отрисовки графиков и алиасов меню.
- Реализация CLI-менеджера плагинов (`plugin install`, `plugin update`).
- Написание исчерпывающей документации, примеров и миграционного гайда со SketchyBar.
